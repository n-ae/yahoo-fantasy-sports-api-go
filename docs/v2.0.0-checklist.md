# v2.0.0 Execution Checklist (Phase D)

**Status:** Draft
**Date:** 2026-07-24
**Prerequisite:** Phases A–C shipped (v1.7.0–v1.9.0). The full v2 API surface
already exists additively in v1.x; v2 is the breaking cut.
**Related:** [v2-roadmap](./v2-roadmap.md), [ADR-0002](./adr/0002-separate-sdk-from-application.md), [ADR-0003](./adr/0003-options-constructor.md)

> v2 forces **every consumer** to change their import path and migrate off the
> deprecated constructor. Do it once, deliberately, as one atomic change. There
> is no partial v2.

---

## 0. Decisions to make first (block everything else)

These are genuine forks; pick before touching code.

- [ ] **D1 — Does `cmd/nba-tool` stay in this module or become a separate module?**
  - *Recommendation:* keep it in this module (per ADR-0002: avoid multi-module
    until the app has external users).
  - *Consequence:* `mattn/go-sqlite3` **stays in `go.mod`** because `cmd/` imports
    it. SDK consumers still only *download* it, never compile it (already true in
    v1). So roadmap step "remove mattn from go.mod" is **not achievable** with the
    app in-module — and per the ADR-0002 amendment the cgo cost is already
    negligible. Accept mattn in `go.mod`; do not chase its removal.
  - Only choose a separate module if you specifically want mattn out of the SDK's
    declared graph — at the cost of two `go.mod`s and two tag streams.
- [ ] **D2 — Modernize the `Cache` interface signature now?**
  - v2 is the only chance to change it without another major. ADR-0003 proposed
    `Get(ctx, key) ([]byte, bool, error)` / `Set(ctx, key, []byte, ttl)`.
  - *Recommendation:* yes — switch to the context-aware `[]byte` signature and
    update `APICache` + call sites. Deferring means a v3 later for a small change.
- [ ] **D3 — Any other breaking cleanups to batch in?** (v2 is the cheap moment.)
  Candidates: unexport `APICache` internals, tighten `Roster` (drop the
  backward-compat `Position` field in favor of `EligiblePositions`), rename any
  awkward exported identifiers. List them here, decide, and do them all at once.

## 1. Pre-flight

- [ ] Cut the v1 maintenance branch from the last v1 tag:
      `git branch v1-maintenance v1.9.0 && git push origin v1-maintenance`
- [ ] Do all v2 work on `main` (Go convention: latest major lives at repo root).
- [ ] Confirm working tree clean and CI green on `v1.9.0`.

## 2. Module path → `/v2`

- [ ] `go mod edit -module github.com/n-ae/yahoo-fantasy-sports-api-go/v2`
- [ ] Rewrite every internal import path to the `/v2` prefix:
      `grep -rl 'yahoo-fantasy-sports-api-go/pkg' --include='*.go' . | xargs sed -i '' 's#yahoo-fantasy-sports-api-go/pkg#yahoo-fantasy-sports-api-go/v2/pkg#g'`
      (covers `pkg/`, `cmd/`, `examples/`; verify no stragglers with a follow-up grep).
- [ ] `go build ./...` and `go vet ./...` clean.

## 3. Constructor finalization

- [ ] Delete the deprecated positional `NewClient(apiKey, apiSecret, db)` and the
      internal `withLegacySQLiteCache` shim.
- [ ] Rename `NewClientWithOptions` → `NewClient` (now the only constructor).
- [ ] Update all call sites: `examples/*/main.go`, `cmd/nba-tool`, and tests
      that use the old positional form.
- [ ] If **D2** = yes: change the `Cache` interface + `APICache` to the
      context/`[]byte` signature and update the cache call sites in `client.go`.

## 4. Relocate the application layer

- [ ] `git mv pkg/service cmd/nba-tool/internal/service` and
      `git mv pkg/repository cmd/nba-tool/internal/repository` (preserves history).
- [ ] Fix up imports and the `cmd/nba-tool/main.go` references.
- [ ] Remove the now-unneeded deprecation `doc.go` comments (internal packages).
- [ ] Delete `pkg/service` / `pkg/repository` from the public surface (the move
      above already does this; confirm nothing outside `cmd/` imports them).
- [ ] **Finish the deferred M5 fixes** (signature changes are fine now):
  - [ ] `SyncTeamsAndRosters`: stop silently `continue`-ing on a missing player —
        count/collect skipped players and surface them (return or report).
  - [ ] `getPlayerPosition`: stop mapping scan errors to `"F"`; distinguish
        "no position" from a real DB error and propagate the latter.
- [ ] Move the service tests with the code; keep them green.

## 5. Dependencies & go.mod

- [ ] If **D1** = keep in-module: leave `mattn/go-sqlite3` in `go.mod` (used by
      `cmd/`); confirm `go list -deps ./pkg/yahoo/...` still shows no sqlite.
- [ ] `go mod tidy`.

## 6. Docs & migration guide

- [ ] Publish `docs/migrating-to-v2.md` with the import-path change and the
      constructor mapping (reuse the roadmap's migration table).
- [ ] Update `README.md`: install line → `@v2`, imports → `/v2/pkg/yahoo`,
      remove the deprecation notice (now removed), update examples.
- [ ] Update `CHANGELOG.md` with a `## [2.0.0]` section listing every breaking
      change (module path, constructor, service/repository removal, Cache
      signature if D2).
- [ ] Flip the retract/versioning docs as needed; the `v1.x` line is now
      maintenance-only.
- [ ] Update the import-direction CI check path to `./v2/pkg/yahoo/...`? No —
      it stays `./pkg/yahoo/...` (paths are module-relative). Just confirm it
      still passes.

## 7. Verification

- [ ] `go build ./...`, `go vet ./...`, `CGO_ENABLED=1 go test -race ./...` green.
- [ ] Import-direction CI check passes.
- [ ] `cmd/nba-tool` builds and prints usage.
- [ ] **Fresh-consumer install check** (repeat the v1.5.0 procedure against v2):
      after tagging, in a throwaway module run
      `go get github.com/n-ae/yahoo-fantasy-sports-api-go/v2@v2.0.0`,
      import `.../v2/pkg/yahoo`, build a tiny program using `NewClient(...)`,
      and `go mod verify`.

## 8. Release & branching

- [ ] Commit on `main`; open PR or fast-forward per your workflow.
- [ ] Tag `v2.0.0` (annotated) — Go requires the `/v2` module path **and** a
      `v2.x` tag for the major to resolve.
- [ ] `git push origin main && git push origin v2.0.0`.
- [ ] `gh release create v2.0.0` with the migration guide linked; mark it Latest.
- [ ] Confirm CI green on the release commit.
- [ ] Confirm the proxy serves it: `curl -s https://proxy.golang.org/github.com/n-ae/yahoo-fantasy-sports-api-go/v2/@v/list`.

## 9. Post-release

- [ ] Announce v1 → v2 in the README badge/section; point new users at v2.
- [ ] Backport only critical fixes to `v1-maintenance` for one cycle, then
      stop.
- [ ] Mark ADR-0002 and ADR-0003 **Accepted / Implemented**; update the roadmap
      to show Phase D done.

---

## Rollback / safety

- The `/v2` path means v2 cannot clobber v1: `v1.x` tags and the
  `v1-maintenance` branch keep working untouched.
- If a v2 defect ships, cut `v2.0.1`; do **not** delete/retag `v2.0.0` (the proxy
  caches it immutably — same rule as the v1 tag cleanup).

## Definition of done

- [ ] `.../v2@v2.0.0` installs cleanly from the proxy and builds against
      `NewClient(...Option)`.
- [ ] `pkg/service` / `pkg/repository` are gone from the public surface; the app
      runs from `cmd/nba-tool`.
- [ ] All M5 items resolved.
- [ ] CI green; migration guide published; `v1-maintenance` branch exists.
